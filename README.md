# CareerPath

An online job / placement portal. **Job seekers** register, keep a profile and resume, search and apply for jobs;
**recruiters** post jobs, search candidates and review applicants; an **admin** manages master data and monitors activity.

This is a cross-platform **Node.js + Express + MySQL** port (styled with **Tailwind CSS**) of an original ASP.NET Web Forms
project. It runs on macOS, Windows and Linux.

---

## Quick start

**Requirements:** [Node.js](https://nodejs.org) 20.12 or newer, and a local **MySQL 8** server that is running.

```bash
# 1. configure your MySQL connection
cp .env.example .env          # Windows: copy .env.example .env
#    then edit .env and set MYSQL_PASSWORD (and MYSQL_USER if you don't use root)

# 2. install and start
npm install
npm start

# 3. open http://localhost:3000
```

On first start the app **creates the `careerpath` database and all tables itself** and adds sample master data
(a country/state/cities, job types, skills, qualifications ...) plus a default admin login.

`npm start` also compiles the Tailwind CSS first (`src/input.css` -> `public/tailwind.css`).
While editing styles, run `npm run dev:css` in a second terminal to rebuild on every change.

### Accounts

| Role       | How to get it                                                                 |
|------------|-------------------------------------------------------------------------------|
| Admin      | Created automatically: **`admin` / `admin123`** (log in at `/login?type=admin`) |
| Recruiter  | Register at `/recruiter/register`, then log in at `/login?type=recruiter`      |
| Job seeker | Register at `/jobseeker/register`, then log in at `/login?type=jobseeker`      |

> Change the default admin password before using this for real.

### Configuration (`.env`)

| Variable         | Default     | Meaning                                                              |
|------------------|-------------|----------------------------------------------------------------------|
| `MYSQL_HOST`     | `127.0.0.1` | MySQL host                                                           |
| `MYSQL_PORT`     | `3306`      | MySQL port                                                           |
| `MYSQL_USER`     | `root`      | MySQL user                                                           |
| `MYSQL_PASSWORD` | *(empty)*   | MySQL password                                                       |
| `MYSQL_DATABASE` | `careerpath`| Database name (created automatically)                                |
| `PORT`           | `3000`      | Port the website listens on                                          |
| `SESSION_SECRET` | random      | Signs login cookies. If unset, everyone is logged out on each restart |

`.env` contains secrets - keep it private. `.env.example` is the safe template.

## Features

**Public** - landing page with live statistics and latest openings, About, Contact, Feedback.

**Job seeker** - registration (account, contact, education, job preferences, technical skills, resume), login,
forgot/change password, edit each profile section, view resume, search jobs (role / location / keyword),
view job details, apply, see "Response Detail" (applications).

**Recruiter** - registration (account + organisation), login, edit organisation profile, post / edit / delete jobs,
see applicants per job, search candidates (skill / degree / city), view a candidate's resume, send a message
(stored in the database; no email server is configured).

**Admin** - dashboard (counts, recent registrations / applications / feedback), master data CRUD
(country, state, city, experience, functional area, job type, qualification, skill), reports of registered
job seekers and recruiters (date filter + delete), applications, jobs offered, visitor feedback.

Every page shows a coloured band with the section (Admin / Job Seeker / Recruiter) and a breadcrumb, and the logo in the
header always links back to the home page.

```
│   └── images/        Images still used by the pages (login illustrations, partner logos, contact/feedback photos)

```

### How a request flows

1. `server.js` matches the URL to a route. Private routes are guarded by `need('<role>')`, which checks the session.
2. The handler reads/writes MySQL through `q.all / q.get / q.run` from `db.js` (always with `?` parameters).
3. The handler builds the page content with helpers from `ui.js` and returns it through `layout()`, which adds the header,
   role band, role menu and footer. All user text is escaped with `esc()`.
4. Tailwind classes in those HTML strings are compiled into `public/tailwind.css`.

### Database tables (created automatically)

`countries`, `states`, `cities`, `experiences`, `functional_areas`, `job_types`, `qualifications`, `skills`
(master data) · `admins` · `jobseekers` · `recruiters` · `jobs` · `applications` · `feedback` · `mails`

Passwords are stored as salted **scrypt** hashes. Foreign keys cascade, so deleting a recruiter removes their jobs and
deleting a job seeker removes their applications.

### Where is the data?

In your local MySQL server, in the database named by `MYSQL_DATABASE` (default `careerpath`). Browse it with MySQL Workbench
or `mysql -u root -p careerpath`. To reset everything: `DROP DATABASE careerpath;` and start the app again.

## Customising

- **Colours / themes:** edit the `--c`, `--c-dark`, `--page` variables per role in `src/input.css`.
- **Add a master-data table:** add an entry to `MASTERS` in `server.js` (and the table in `db.js`); the admin menu
  entry goes in `adminMenu()` in `ui.js`.
- **Menus:** the role menus are arrays in `layout()` / `adminMenu()` in `ui.js`.

## Troubleshooting

| Problem | Fix |
|---|---|
| `Could not connect to MySQL ... Access denied` | Set the right `MYSQL_USER` / `MYSQL_PASSWORD` in `.env`. |
| `Could not connect to MySQL ... ECONNREFUSED` | MySQL isn't running, or `MYSQL_HOST` / `MYSQL_PORT` is wrong. |
| `EADDRINUSE: address already in use :::3000` | An older copy is still running. Stop it (Ctrl+C) or set another `PORT` in `.env`. |
| Page looks unstyled / old | Run `npm run build:css`, restart, then hard-refresh (Cmd+Shift+R / Ctrl+F5). |
| Logged out after every restart | Set a fixed `SESSION_SECRET` in `.env`. |

## Notes

- The original SQL Server database shipped with the project was empty (all zero bytes), so the schema was rebuilt from the
  original C# code and its stored-procedure calls.
- "Send message" saves to the `mails` table; real email delivery (SMTP) is not implemented.
- The site is intended for local / demo use. Before exposing it publicly add HTTPS, CSRF protection, rate limiting and
  change the default admin password.
